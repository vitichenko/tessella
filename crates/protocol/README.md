# tessella-protocol

> Canonical Data Transfer Objects (DTOs), network wire protocols, and cryptographic proof contracts shared between Tessella (Data Plane) and Musivum (Control Plane).

## Responsibility

`tessella-protocol` establishes the zero-business-logic boundary contracts across the distributed cluster. It defines:
- Wire serialization formats (`serde`, `bincode`, `rkyv`).
- Inter-node and orchestrator RPC interfaces (`WorkerRegistration`, `WorkerAssignment`, `AnnounceRequest`, `AnnounceResponse`).
- Cryptographic Proof-of-Compute mechanisms (`WorkTicket`, `WorkProof`, `ReplayCache`, Ed25519 payload signatures).
- Cluster membership and gossip protocols (`WorkerGossipMsg`).

It has zero dependencies on internal compute (`candle`), storage (`rusqlite`), or HTTP frameworks (`axum`), serving as the foundational leaf crate for both the worker daemon and the orchestrator.

## Proof-of-Compute Specification

The Proof-of-Compute economy relies on asymmetric cryptographic verification:
1. **`WorkTicket`**: Issued by the orchestrator per session grant. Encodes the client's public key, target model, request tier (VIP/Standard/Leech), and expiration timestamp.
2. **`WorkProof`**: Generated by each serving worker upon completing its forward pass over its assigned contiguous layer range. Chains input/output activation hashes, worker identity signature, and the parent ticket.
3. **`ReplayCache`**: Fixed-capacity sliding window cache preventing replay attacks on signed tensor frames and capabilities.
